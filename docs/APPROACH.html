A Judge That Learns from an Expert

Plata track · Hack Day Barcelona 2026

1A polite answer can still be wrong

The assistant agrees: Uber, August, 526 MXN. The bank context says completed transactions total 426 MXN. Plata's expert labelled this conversation bad. The only way to catch it is to recompute.

Крючок: дать прочитать 526 против 426 — поймать это можно только пересчётом.

2The task in one picture

Learn an expert's rules from labelled conversations. Save them as artifacts: rules plus an explanation. Then judge new conversations. The score rewards accuracy and a clear explanation.

Две части оценки — точность и понятное объяснение; строили под обе.

3How adapt learns

Three steps, all from the training set. A rule that raises even one false alarm on an expert-approved conversation may not decide. It moves to boundary and stays in the explanation as a rejected hypothesis.

Главный аргумент: 18 отвергнутых гипотез — учимся у меток эксперта, а не у себя.

4How eval decides

Rules are checked in priority order. The first violated rule gives bad, with the assistant's own quote. If none is violated, the answer is good.

eval намеренно простой: первое нарушенное правило по приоритету — bad с цитатой, иначе good.

5The explanation is the implementation

One manifest produces the explanation and drives the predictions. Its SHA-256 is stored in run_meta.json. The text a judge reads is the rule set that predicts.

Jury criterionWhat the explanation shows
Clear criteriaEvery rule as a plain condition, e.g. “Recalculate completed merchant transactions before confirming a proposed amount”
Clear prioritiesRules sorted by priority; the first violation wins
Links to training examplesReal train IDs with the expert's labels and quotes
Clear boundariesRejected hypotheses, each with its condition
Consistency with the implementationSame manifest for text and predictions; hash in run_meta.json

An independent structural check found all five present on every adapt run. Jury points themselves are not claimed.

Объяснение и есть реализация: один манифест, SHA-256 в run_meta.json.

6Optional model layer

A model answers yes, no or unknown, and must quote the assistant. It can also propose rules for bad cases nothing explains. Every proposal is verified on all of train first.

No API key: everything stays deterministic. Does induction rediscover rules? measuring

Модель опциональна: без ключа всё детерминировано; качество индукции пока измеряется.

7Results

Macro accuracy: the mean over four topics. The public test is not a clean holdout, so read the cross-validation bar as the honest estimate.

Честно: 0,950 — не чистый holdout, ориентир — CV 0,922; голая модель ещё измеряется.

8Where it fails, honestly

Meaning, not numbers

Public 4, train 1: all semantic.

New expert rules

Without a model, not found. Rediscovery: measuring

Not a clean holdout

Seen in design. Expect nearer 0.922.

Blind audit: two defects, both fixed.

  • Empty dialog: eval crashed; now returns a verdict.
  • Leading “Hello.”: flipped 3 verdicts. Rules now follow roles.
  • Post-fix re-audit: measuring

Ошибки — в смысле, а не в числах; слепой аудит нашёл два дефекта, оба исправлены и покрыты тестами.

9Try it

Docker containers get no API key. Start each adapt with an empty artifacts folder. Bring your own example: a dialog and a context as two JSON files.

mkdir -p out/public_input out/public_artifacts out/public_output
python3 src/prepare_inputs.py --train data/public_train.csv --test data/public_test.csv --out-dir out/public_input
docker build -t plata-judge .

1Adapt

docker run --rm \
  -v "$PWD/out/public_input:/input:ro" \
  -v "$PWD/out/public_artifacts:/artifacts" \
  plata-judge adapt

2Eval

docker run --rm \
  -v "$PWD/out/public_input:/input:ro" \
  -v "$PWD/out/public_artifacts:/artifacts:ro" \
  -v "$PWD/out/public_output:/output" \
  plata-judge eval

3Demo, one command

python3 -S demo/judge_demo.py \
  --id 100a727946a7a45a72c46771e608090f \
  --artifacts out/public_artifacts
